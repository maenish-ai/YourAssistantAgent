# Security audit — preliminary

Scope: static inspection and existing targeted tests, not a penetration test. Findings are observations to verify and fix, not claims that the entire system is secure.

1. **High: browser bridge is reachable by arbitrary web origins.** `src/yaa_lite/browser_bridge/server.py` binds loopback but responds with `Access-Control-Allow-Origin: *`, accepts unauthenticated `/hello`, `/next-command`, and `/command-result`, and has no request body bound in `_json_body`. A malicious web page able to reach localhost can potentially read queued commands, impersonate an extension, or submit fabricated results. Localhost is not an authentication boundary. Mitigation in this branch rejects ordinary web origins, requires a custom header, bounds request bodies and sets socket timeouts. This is not authentication: another extension or local process can still impersonate the bridge client. A paired credential and a real-browser compatibility test remain required. Reload the updated extension after upgrading. Do not expose bridge publicly.
2. **High: voice model supply chain.** `tools/prepare_bundled_female_voice.py` downloads a mutable Hugging Face `main` model and archive with only minimum-size checks. This branch pins the model to Hugging Face revision `f89f1aec8e6486871ffdf8d878c5a39eaf918d60` and checks SHA-256 for the raw model, configuration and newly downloaded phonemizer archive. The Hugging Face model metadata reports MIT (checked 2026-11-05); underlying dataset rights, archive licensing, previously extracted cached assets and redistribution still require verification before release. Existing `LICENSE-NOTICE.md` describes older models and is not evidence for the current Android voice.
3. **Medium: mobile memory confidentiality.** Owner notes and task history are stored in ordinary SQLite; no encryption of note content was established. Explicit notes can be included in model context, hence sent to the configured cloud provider. Avoid passwords and confidential content; implement explicit consent and encrypted storage before claiming sensitive-memory support.
4. **Medium: user-wide remote pairing.** Relay uses separate derived role credentials and AES-GCM; server stores bounded queues in memory. Per-device enrollment/revocation and independent cryptographic review are not established. Real cross-network replay/reconnection tests remain required.
5. **Medium: trust and irreversible actions.** The desktop agent uses UI observation and whole-task approval. Generic clicks can have effects not independently verifiable from UI; page/desktop text is untrusted. Specific final approval and verification are needed before claiming safe autonomous publishing or financial operations.
6. **Build signing.** Existing workflows optionally use secrets for signing; an unsigned debug build is not a signed release or necessarily upgrade-compatible with an existing installation. No Windows or Android production signing secrets are present in this environment.

No secrets are intentionally included in generated patches. This report does not assert an exhaustive scan, dependency review, platform compliance assessment, or third-party penetration test.
