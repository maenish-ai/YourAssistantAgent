# YourAssistantAgent 4.6 — إقران QR واتصال تلقائي

النسخة تضيف ربطاً عبر خادم وسيط، بدون Tailscale أو كتابة عنوان الكمبيوتر ومفتاحه على الهاتف.
مصدر Windows هو 4.6، وتطبيق Android هو 1.2. يجب تحديث التطبيقين.

**الخادم يحتاج استضافة عامة دائمة أولاً.** ملفات المصدر وAPK لا تنشئ استضافة وحدها، ولا يوجد رابط خادم عام مضمن أو ادعاء أنه منشور مسبقاً.
بعد إعداد الخادم مرة واحدة، الاستخدام اليومي يصبح فتح برنامج الكمبيوتر ومسح QR أول مرة فقط، ثم يعيد الهاتف والكمبيوتر الاتصال تلقائياً.

## للمستخدم بعد تجهيز الاستضافة

1. ثبّت نسخة الكمبيوتر الجديدة وافتح قفل البرنامج. ارفع المصدر وابنِ المثبّت عبر GitHub Actions، أو شغّل المصدر باستخدام Python.
2. افتح **الإعدادات ← الإقران التلقائي QR** واضغط **استيراد ملف إعداد الخادم** واختر `desktop-setup.json` الذي جهّزه مسؤول الاستضافة.
3. يبدأ اتصال الكمبيوتر بالخادم في الخلفية. حدّث الحالة حتى تظهر رسالة أن الخادم متصل.
4. اضغط **عرض QR لإقران الهاتف**.
5. افتح تطبيق Android الجديد واضغط **مسح QR**. اسمح للكاميرا وامسح الرمز من شاشة برنامج الكمبيوتر.
6. تُحفظ بيانات الاقتران مشفّرة على الهاتف. بعد ذلك يحاول الاتصال تلقائياً عند فتح التطبيق، وعند عودة الكمبيوتر أو الخادم بعد انقطاع.
7. زر **قطع الاتصال** يوقف إعادة الاتصال على هذا الهاتف حتى تضغط اتصال أو تمسح QR مجدداً. زر **اتصال** يعيد الاتصال المحفوظ دون تعبئة خانات.

الرمز يمنح الوصول إلى الكمبيوتر. لا تنشره؛ تغيير مفتاح الاقتران من Android وGitHub يلغي وصول الهواتف القديمة. الرمز اعتماد دائم حتى تغييره، وليس رمزاً ينتهي بعد أول مسح.
الكمبيوتر يبقى مستيقظاً والبرنامج شغّالاً ومفتوح القفل. لا تُضاف ميزة الإيقاظ من السكون أو تجاوز قفل Windows في هذا التحديث.

## الشاشة والملفات والأوامر

كل وظائف نسخة 4.5 تستمر عبر الربط الجديد: المحادثة، ZIP إلى GitHub بمعاينة، الجروبات والمنشورات، سطح المكتب اليدوي، مساعد الكمبيوتر، والملفات في الاتجاهين.
فعّل **التحكم بالكمبيوتر** من إعدادات Windows لإتاحة الشاشة والملفات، وفعّل الخيار المنفصل لمساعد الكمبيوتر الذكي عند رغبتك.
التعليمات التفصيلية والقيود موجودة في `README_V450_AR.md`.

- ZIP إلى GitHub: حتى 20 MiB، ولا يبدأ Commit/Push قبل موافقتك.
- نقل الملفات العادي: حتى 256 MiB، على دفعات مع تحقق SHA256 نهائي.
- الملفات لا تُحمل كاملةً في ذاكرة الهاتف أو الخادم الوسيط. الخادم يمرر دفعات مشفّرة فقط؛ التجميع المؤقت يتم على الكمبيوتر.
- المحادثة وعناصر الواجهة التي يستخدمها المساعد تظل تُرسل إلى Groq وفق الإعداد السابق. صور الشاشة ومحتويات الملفات لا تُرسل إلى Groq.
- عند انقطاع الشبكة، راجع الحالة والمحادثة قبل تكرار أمر قد يكون وصل. لا توجد إعادة تنفيذ تلقائية بأرقام طلبات جديدة.
- الهاتف يتابع الاتصال أثناء فتح التطبيق؛ لا توجد خدمة إشعارات خلفية.

## إعداد الاستضافة مرة واحدة — VPS وDocker

تحتاج خادماً عاماً، ونطاقاً/نطاقاً فرعياً يشير إليه، وDocker مع Compose. فتح 80 و443 يكون على الخادم العام؛ لا تحتاج فتح منفذ على راوتر البيت.
لا يشمل المشروع شراء الخادم أو النطاق. راجع تكلفة الاستضافة وحركة البيانات؛ عرض الشاشة ونقل ملفات كبيرة يزيدان الاستهلاك.

من المصدر على الخادم:

```sh
cd relay_server
python3 setup.py --domain relay.example.com
docker compose up -d --build
```

`relay.example.com` مثال، استبدله بالنطاق الذي تملكه والموجّه إلى الخادم.
يُنشأ `.env` و`desktop-setup.json` محلياً؛ كلاهما يتضمن مفتاح تسجيل خاص بالمالك. الملفات مستثناة من Git ولا تُطبع المفاتيح في مخرجات الإعداد.
انقل `desktop-setup.json` إلى جهاز Windows واستورده في برنامج المساعد. لا تنشر الملف مع المصدر.
Caddy ينشئ HTTPS تلقائياً عندما يكون النطاق صحيحاً ومنافذ إصدار الشهادة متاحة.
عنوان فحص الخادم: `https://نطاقك/health`؛ يعرض الحالة فقط دون بيانات الأجهزة.

## بديل: خدمة استضافة Python مثل Render

الخادم يعمل بمكتبة Python القياسية دون متطلبات إضافية:

- أمر البناء: `python -m py_compile relay_server/server.py`
- أمر التشغيل: `python relay_server/server.py`
- `RELAY_BIND=0.0.0.0`
- `RELAY_ENROLLMENT_KEY`: مفتاح عشوائي قوي بطول 32 حرفاً أو أكثر، يُحفظ كمتغير سري.
- `PORT`: القيمة التي يوفّرها مزوّد الاستضافة.
- فحص الصحة: `/health`.

استخدم عملية/نسخة واحدة؛ طوابير الربط مؤقتة داخل العملية. لا يتطلب الخادم قرصاً دائماً. يعيد الكمبيوتر تسجيل اتصاله بعد إعادة تشغيل الخادم دون إعادة مسح QR.
اختر خطة مناسبة للبقاء متصلاً دائماً وحدود البيانات. لا نفترض أن الخطط المجانية توفر ذلك.
بعد النشر يُستورد عنوان HTTPS ومفتاح تسجيله في برنامج Windows مرة واحدة. يمكن تنفيذ النشر عبر إضافة Render بعد ربط حسابك ومراجعة الخطة.

## ملاحظات البروتوكول والاختبار

الرسائل تستخدم AES-256-GCM، بوسم مصادقة مرتبط باتجاه الرسالة ورقم الطلب والقناة. مفتاح الاقتران لا يصل إلى الخادم الوسيط؛ مفاتيح أدوار الخادم مشتقة بشكل منفصل.
سجل أرقام الطلبات على الكمبيوتر يمنع إعادة تنفيذ الرسائل المكررة حتى بعد إعادة تشغيل موصل الكمبيوتر. يتحقق أيضاً من وقت الطلب؛ اضبط وقت وتاريخ الهاتف والكمبيوتر.
هذه ليست طبقة تسجيل دخول لمستخدمين عامّين أو خدمة تجارية متعددة المستأجرين؛ الخادم الشخصي محمي بمفتاح تسجيل المالك.
الكاميرا والاتصال عبر شبكة عامة حقيقية يحتاجان تجربة على جهازك؛ الاختبارات المحلية لا تعني أن خدمة عامة منشورة بالفعل.
